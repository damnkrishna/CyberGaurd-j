## 3. Year 1: Internship Plan (R&D & Lab Content)

### 3.1 Priorities (in order)
1. **Deliver at work.** Quality and on-time lab content is what earns the PPO.
2. **Learn how INE builds labs.** Environment design, vulnerability setup, reset scripts, documentation.
3. **Study certs after hours** using whatever platform access you have.
4. **Build visible output** (documented labs, write-ups, detection rules).

### 3.2 First 2 Weeks
- [ ] Get platform access confirmed. Ask exactly what you can use.
- [ ] Ask HR/manager about exam voucher and reimbursement policy for interns.
- [ ] Understand how tasks are assigned and how work is reviewed.
- [ ] Learn the lab tooling the team uses (ask which of Docker, Ansible, Terraform/CloudFormation, AWS, VMs they rely on).
- [ ] Set up a private notes system (Obsidian/Notion), structured by **MITRE ATT&CK tactic** and **tool**.

### 3.3 Cert Order During Internship

| Order | Cert | Focus | Target timing | Notes |
|---|---|---|---|---|
| 1 | **eEDA** | Defensive: Windows event logging, auditd, hardening, CIS benchmarks | Weeks ~3–8 | Closest to your existing detection work |
| 2 | **eJPT** | Offensive basics: enumeration, pivoting, Metasploit, basic web attacks | Weeks ~8–14 | Entry-level practical exam |

Approach: study using work access, take notes, and do labs. **Take the exam only when you can solve the labs without notes.**

### 3.4 Money Plan
- **Best case:** INE sponsors vouchers after you show good work (ask around month 3–6, after finishing the relevant path and doing solid work).
- **Fallback:** Pay for **one voucher yourself** (eJPT ~US$249, verify price), pass it, then use that as proof of commitment.
- **Don't** spend on bundles you don't need if you already have platform access.

### 3.5 Working Rhythm (Sprint → Recovery)

Your stated pattern: 2–3 months of obsessive work, then 1–2 months of lighter load, while always meeting core job responsibilities.

| Phase | Duration | After-hours focus | Non-negotiables |
|---|---|---|---|
| **Sprint 1** | ~2–3 months | eEDA course + labs, then eJPT course + labs | 9–6 deliverables on time |
| **Recovery 1** | ~1–2 months | Light reading, notes cleanup, boxing, maybe travel while working remote | 9–6 deliverables on time |
| **Sprint 2** | ~2–3 months | Exam attempts, Active Directory basics, start next track | 9–6 deliverables on time |
| **Recovery 2** | ~1–2 months | Rest, review feedback, PPO prep | 9–6 deliverables on time |

### 3.6 Guardrails (so the system keeps working)
- **Recovery must stay in recovery.** Having a planned break is the whole point. Don't turn it into another sprint.
- **Watch for work quality slipping.** If a deliverable is late or sloppy, scale back the night study the same week.
- **Keep boxing and sleep fixed.** Treat them as part of the training, not optional.
- **Keep at least a little contact with people** (friends, family) even in sprints. Isolation for 2–3 years is a risk for motivation, not a strength.
- **Don't broadcast progress too early.** Let finished certs and good work speak.

### 3.7 PPO Conversion Checklist (months 9–12)
- [ ] Consistent, documented lab/R&D deliverables
- [ ] Positive feedback from manager and teammates
- [ ] eEDA and/or eJPT completed
- [ ] A short "impact summary" (labs built or improved, bugs fixed, content shipped)
- [ ] Conversation with manager about PPO terms, role, and cert/benefit policy
- [ ] Salary expectations researched (target upper end of junior band; **12–15 LPA was the working assumption, not a promise**)

## 4. Years 2–3: Full-Time Specialist

### 4.1 Goals
- Convert to full-time, claim all employee benefits (verify them).
- Move from "junior content" to engineer / senior contributor.
- Clear the mid and advanced certs.

### 4.2 Certification Roadmap

**Red Team track**
| Stage | Cert | Purpose |
|---|---|---|
| Entry | eJPT | Foundation |
| Mid | eCPPT | Core network/system exploitation |
| Advanced | eCPTX | Active Directory, evasion, lateral movement |

**Next-Gen / Architecture track**
| Stage | Cert | Purpose |
|---|---|---|
| Foundation | eEDA | Enterprise defense administration |
| Cloud | Cloud security path (INE or AWS/Azure security cert) | Cloud architecture and security |
| Emerging | eAIS (verify it exists and its scope) | AI/LLM system security |

**Optional external certs (employer-reimbursed if allowed):** OSCP, AWS Certified Security – Specialty, or a CISSP-type cert later for architect roles.

### 4.3 Year-by-Year Targets

| Period | Main goal | Certs |
|---|---|---|
| Months 0–12 (intern) | Do great work, learn lab architecture, build notes | eEDA, eJPT |
| Months 12–24 (full-time) | Deepen offensive and cloud skills | eCPPT, one cloud security cert |
| Months 24–36 | Advanced track | eCPTX and/or eAIS |

Don't try to do everything. **Two advanced, well-earned certs beat eight shallow ones.**

## 5. Years 3–5: Path to Security Architect

### 5.1 Skill Stack to Build
- **Offensive:** Active Directory attacks, web/API testing, post-exploitation
- **Defensive:** Detection engineering, SIEM/EDR, logging architecture
- **Cloud:** AWS/Azure identity, networking, logging, IaC security
- **Architecture:** Threat modeling, zero trust, secure design reviews, risk and compliance basics
- **Engineering:** Python, PowerShell, Bash, automation, IaC (Terraform/Ansible)
- **Communication:** Writing reports, explaining risk to non-technical people

### 5.2 Career Moves

| Timeline | Move |
|---|---|
| Year 3 | Consider a senior role inside INE, or start looking outward with 2+ years of R&D experience and 2–3 solid certs |
| Year 3–4 | Switch to a consulting firm, product security team, or fintech/bank security team if growth or pay stalls |
| Year 4–5 | Target Security Engineer → Senior Security Engineer → Security Architect |

### 5.3 What Makes The Jump Work
- Public proof: blog posts, lab write-ups, detection rule repos, conference talks (even small ones)
- Having built real labs and detection content, not just passed exams
- Strong interview stories: "Here's a problem I designed, built, and defended"
- Salary: research live market data for your role/city when you're 12 months from switching. The 28–40+ LPA figure from the chat is a **possible** outcome, not a forecast.
